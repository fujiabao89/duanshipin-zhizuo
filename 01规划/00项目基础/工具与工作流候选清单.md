# 工具与工作流候选清单

> 用途：长期保存用户分享、且可能对项目某个阶段有价值的工具与工作流，避免“当前用不上”被误判为“以后也没用”。  
> 使用方式：每次收到新工具或案例，先做证据核验，再分别判断当前价值、未来价值、复核时点与风险。本文件只保存项目级候选，不替代单条视频执行稿。

## 判断状态

| 状态 | 含义 |
|---|---|
| 当前采用 | 已确认适合当前阻塞，可以进入现行流程 |
| 当前借鉴 | 不整套接入，只吸收其中适合当前项目的方法 |
| 到点复核 | 有长期价值，但需等到指定阶段再测试或决定 |
| 待验证 | 信息或证据不足，暂不作采用判断 |
| 不采用 | 已有足够证据表明与项目目标、成本或风险不匹配 |

## Remotion 官方 Codex 插件

- 核验结论：Remotion 官方确实维护 Codex 插件，可帮助新建 Remotion 项目并提供程序化视频制作技能。2026-09-04，用户明确决定安装；官方插件 `remotion@openai-curated` 已安装并启用，插件版本为 1.0.3、本机安装标识为 `11c74d6b`，不依赖额外 ChatGPT 应用或外部账号。它是基于 React 的视频制作框架，不是剪映控制器，也不是剪映 MCP。
- 对当前项目的能力重叠：录屏裁切、真人小窗、字幕、关键词高亮、音频、转场、横竖屏画布和动效，HyperFrames 与 Remotion 都能完成；HyperFrames 已有完整成片实证，因此现在迁移没有明显收益。
- 当前使用边界：安装仅代表 Remotion 能力已经可用，不等于把现有项目从 HyperFrames 迁走。同时维护 HTML/GSAP 与 React/Remotion 两套时间线、依赖和渲染流程，会让同一套字幕、布局和动效重复建设，因此正式制作时必须明确指定框架并隔离工程。
- Remotion 的长期独特价值主要在模板参数化、批量生成、Player / Editor 以及服务端或云端规模化渲染。当项目真正进入“同模板大量变体”或“把视频生成能力做进产品”的阶段，再测试更合适。
- 到点测试方法：使用同一份 10—15 秒素材，同时制作连续真人小窗、两行字幕和关键词高亮、一个录屏片段、一个四节点目录动效，并生成 16:9、9:16 和多套文字版本；比较首次完成时间、改稿时间、音画同步、重排量和渲染稳定性。
- 官方来源：[Remotion Codex 插件说明](https://www.remotion.dev/docs/ai/codex-plugin)、[Remotion Agent Skills](https://www.remotion.dev/docs/ai/skills)

## 剪映 / CapCut MCP

- 核验结论：截至 2026-09-04，未发现 OpenAI/Codex 官方或字节跳动、剪映、CapCut 官方发布的剪映 MCP 插件；本机也没有安装或配置名称包含 CapCut、JianYing 或剪映的 MCP。公开可见的同名项目均属于第三方实现。
- 它们的主要新增价值不是替代 HyperFrames 输出更稳定的成片，而是“由 AI 拼装一个可在剪映或 CapCut 中继续手工修改的草稿”。最终预览、细调和导出通常仍要回到剪映或 CapCut 完成。
- 主要风险：多数方案直接读取或仿写未公开的草稿格式；软件自动更新、草稿加密或字段变化都可能导致兼容失效、工程打不开或已有字段丢失。部分项目还包含 URL 下载、云端上传、外部域名、明文云存储密钥配置或删除草稿能力，不能直接取得正式原片和工程目录权限。
- 当前相对成熟的候选是 [VectCutAPI](https://github.com/sun-guannan/VectCutAPI)：能从零生成带素材、字幕、效果和关键帧的剪映 / CapCut 草稿，但不能可靠接管已有复杂工程；源码包含外部域名和可选 OSS 上传，采用前必须先做源码与网络权限审查。
- [JianYing MCP](https://github.com/hey-jian-wei/jianying-mcp) 可创建和导出剪映草稿，但仓库维护与当前版本兼容证据不足；[capcut-mcp](https://github.com/JmsLdrn/capcut-mcp) 明确说明自己不是 CapCut / 字节跳动官方项目，并承认私有草稿格式会随更新变化。
- 如未来确有需求，必须先使用 10—20 秒复制素材、空白测试草稿和独立目录；关闭剪映后再写入，禁用云上传与删除权限，保留原工程备份，并以“草稿可打开、字段无丢失、能正常导出”为验收标准。未通过前不得接入真实视频工程。

## GreenSock gsap-skills

- 核验结论：这是 GSAP 官方团队 GreenSock 发布的 AI Agent 技能库，不是独立剪辑软件，也不是安装后直接出现的一组可视化特效按钮。
- 对当前项目有用：`gsap-core`、`gsap-timeline` 和 `gsap-performance` 可以帮助 HyperFrames 更准确地完成关键词入场、左右画面分阶段出现、动作衔接、缓动和性能控制；`gsap-plugins` 中的 SplitText、Flip、CustomEase、SVG 等能力可在具体镜头需要时选用。
- 与当前画面的对应关系：Codex 图标弹出可使用短促缩放与回弹；豆包/Codex 对比可用单一时间线按口播先左后右建立；论文高亮、圈注、路径和文字逐句出现可使用 SVG、SplitText 或自定义缓动。
- 当前不整包照搬：ScrollTrigger、ScrollSmoother、Draggable、React/Vue/Svelte 等内容主要服务网页滚动和交互，不应该成为视频渲染的时间驱动。HyperFrames 仍需坚持单一、可暂停、可定位、可重复渲染的确定性时间线。
- 当前行动：把它作为官方 GSAP 参考库选择性借鉴；先在第 1 条的 10—20 秒样片中验证“口播锚点同步”，出现具体能力缺口后再决定是否全局安装对应技能。
- 官方来源：[GreenSock gsap-skills](https://github.com/greensock/gsap-skills)、[GSAP core skill](https://github.com/greensock/gsap-skills/blob/main/skills/gsap-core/SKILL.md)、[GSAP plugins skill](https://github.com/greensock/gsap-skills/blob/main/skills/gsap-plugins/SKILL.md)
