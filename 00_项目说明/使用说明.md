# 使用说明

## 人工阅读

第一次接触仓库时，先读《项目定位》和《当前版本》。准备制作视频时进入《单条视频完整流程》，再根据当前阶段跳转到对应方法或规范。不要从单条案例反向推断全部视频都应采用同样的画幅、音效数量或动效风格。

## AI Agent 使用

AI 先读根目录 `AGENTS.md`，根据任务类型按需读取。处理具体视频时，必须先读该视频的 `项目卡.md`；只有当前任务确实涉及历史原因时，才读取 `99_归档/`。

## 文件之间的关系

```text
项目说明：我们在做什么
总工作流：先做什么、后做什么
内容方法：内容怎么写好
制作规范：视频怎么做好
发布规范：怎么正确发布
运营与研究：什么更值得做
视频案例：这一次实际发生了什么
资产库：什么可以重复使用
归档：哪些内容已经退出当前体系
```

同一条规则只保留一个权威来源。其他文件应引用它，不复制整段内容。

## 新增一条视频案例

1. 在 `06_视频案例/` 下建立 `第NNN条_标题/`。
2. 先创建 `项目卡.md`，记录状态、目标、特殊要求、待确认项和全局规则入口。
3. 正式脚本使用 `最终脚本.docx`；制作中的版本稿和原片保留在受控的本地工作区，不要求全部进入公开仓库。
4. 视频复杂时才增加 `分镜.md` 或 `制作说明.md`。
5. 实际发布信息、数据、异常和经验写入 `发布复盘.md`。
6. 案例中发现的新规律先标记为观察或待验证；跨案例验证后再更新全局规范和工作流变更记录。

## 状态与证据

- 已确认事实：有直接文件、用户确认、真实页面或可靠来源支持。
- 用户制作约束：用户决定以后怎么做，但不等同于平台官方规则。
- 外部经验：可作为行动参考，但必须注明来源和适用边界。
- 待验证：证据不足或只出现一次，不写成确定结论。

## 归档与清理

旧方案进入 `99_归档/` 后不再作为当前入口，也不继续修订。临时缓存和可重建过程文件按制作流程清理；最终脚本、原片、成片、封面、证据、授权记录和发布复盘不得因清理丢失。

## 公开仓库边界

当前仓库曾采用白名单式 `.gitignore`，主要公开 Markdown 与已确认封面。文档中记录的本地 macOS 路径用于资产追溯；在 Windows 克隆中不存在，不代表对应资产已删除。涉及公开范围、脚本、原片或工程上传时，应先重新确认隐私、版权和仓库策略。
