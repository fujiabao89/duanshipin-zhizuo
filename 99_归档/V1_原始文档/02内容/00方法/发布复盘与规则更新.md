# 发布复盘与规则更新

> 建立：2026-09-06。复盘是五阶段流程的最后一环，同时为下一条的选题、脚本、制作、封面和文案提供依据。
> 本文的观察时点与实验安排是工作建议，不是平台推荐周期。记录真实数据，缺什么写什么，不补造。

## 一、发布前留一个可验证的判断

在本条“发布与复盘.md”写下：

- 主要观众是谁，这条最希望帮他解决什么；
- 本条优先看什么结果，如有效提问、收藏、关注或作品尝试反馈；
- 标题和封面让观众预期会看到什么，成片在哪里兑现；
- 这一条试了什么变化，例如标题从工具介绍改成个人实践、减少背景音乐、换一个场景标签；
- 为什么预计它有帮助。

一次尽量只明确一个主要实验。实际制作同时变了多处也照实记录，不能事后把结果都归功于一个标签。

## 二、什么时候看

| 时点（建议） | 看什么 | 不急着下什么结论 |
|---|---|---|
| 发布后首次核对 | 是否公开、审核状态、音画与封面、文案有没有粘错 | 前几分钟播放少不直接认定限流 |
| 约24小时 | 初步播放、观看、互动与评论；有没有明显技术或事实问题 | 小样本不推出固定规律 |
| 约72小时 | 做一次主要复盘，和此前同类内容、发布前预期对照 | 不把单条的高低直接解释为标题或标签造成 |
| 约7天，按需 | 教程、搜索型内容是否有后续观看与问题 | 不要求每条都做完整周报 |

这是观察计划，不是已经设置了自动提醒或后台监测。需要定时提醒时再按用户要求安排；如果第一次检查已晚于这些时点，就记录当前数据，过去的数据缺失即缺失。

## 三、记录哪些数据

优先使用抖音创作者后台当时真实提供的指标：

- 数据采集时间、发布时间、统计区间、作品时长、作品状态；
- 播放量、平均观看时长、完播率；
- 后台若有，记录2秒跳出、5秒留存及留存曲线，沿用页面准确名称和定义；
- 点赞、评论、收藏、分享，以及能明确归因到本条的新增关注；
- 后台若提供，记录推荐、搜索、主页等流量来源与搜索词；
- 观众具体问了什么、误解了什么、说哪个例子有用；
- 制作耗时、主要返工位置、BGM与音效是否帮助或干扰理解。

没有展示曝光量或点击率，就不要自行编一个“封面点击率”。不要把视频自动播放当成点击；账号总涨粉也不直接当成本条涨粉。

记录比例时同时保留分子、分母或后台原始口径。不同视频长度、选题、发布时间、来源人群、活动和投放都会影响表现，比较前先注明。暂时没有可比历史样本，就以观察为主，不设一个所有视频通用的及格线。

## 四、从问题到下一步

| 观察 | 先检查什么 | 可以提出的下一条实验 |
|---|---|---|
| 开头流失明显 | 标题承诺是否对得上开场；是否过长铺垫、说话僵直、收音差 | 开头更早给真实结果，或改变试录／提词方式 |
| 中段掉得快 | 对应时间是否重复、难懂、证据太小、动效不同步 | 缩短一个解释段，用具体演示替代抽象文字 |
| 标题很吸引但评论说不符 | 承诺是否超出视频成果；是不是只展示却写成教程 | 缩小承诺范围，保留有依据的反差 |
| 有用的收藏与问题，但播放不高 | 是否是较窄的实用需求，搜索来源和长尾反馈如何 | 延伸具体教程；不急着把内容改成泛娱乐 |
| 评论集中于某个未讲清的步骤 | 是有效需求还是信息遗漏 | 在下一条补足，必要时更新来源或更正说明 |
| 标签换过后播放变化 | 其他变量是否同时变化，实际人群与搜索词是否相关 | 作为线索保存，不声称“这个词带来多少播放” |
| 技术质量过关但制作太久 | 哪些重复返工可提前用样片或清单避免 | 每次只优化最耗时的一步，记录节省情况 |

这些都是排查顺序与实验提议，不是单指标的因果判定。

## 五、一页复盘格式

在本条“发布与复盘.md”直接追加：

```text
采集时间／距发布多久：
作品与平台状态：
数据及口径（缺失写未提供）：
三个有代表性的观众反馈（概述，隐去无关个人信息）：
原先的判断：
实际发生的事：
可能原因与其他解释：
这次值得保留的一件事：
下次最先改的一件事：
需要用户判断的审美或表达取舍：
结论状态：观察记录／待再验证／用户确认采用
回写了哪条规则及适用范围（如有）：
```

不为了写复盘去反复发布同一个视频。标题、封面并排比较是发布前的偏好比较，不自动构成流量A/B测试；两条不同视频的数据也只是参考。若平台日后提供适用的对照测试功能，再另行核对如何使用。

## 六、怎样更新长期规则

1. 客观错误与可靠修复，例如字幕残留、导出无声，修复并核验后可形成技术检查项。
2. 视觉与表达偏好必须由用户认可实际结果后记录。新封面分析仍保持附加文档，不能因本次新增发布流程覆盖已确认风格。
3. “某个标题句式、标签组合更好”先保留为假设；有多条可比作品和反馈后，再判断适用范围，并由用户决定是否采用。
4. 不写“必爆”“算法就喜欢这个”之类不可验证规则。已有规则不好用时写明证据和修改理由，保留必要的变更说明。

## 七、清理时保留什么

保留最终发布文案与话题、发布链接和时间、简短的数据记录、必要来源证据和有用复盘。采集数据产生的临时截图、重复导出、一次性脚本在信息核对并记录后清理；用户原始提供的素材不擅自删。

若外部数据暂时无法访问，明确“待用户提供数据／待复盘”，继续下一条已具备条件的工作，不为等待复盘保留大量工程缓存。

## 八、异常诊断与持续学习

2026-09-06补充。用户希望助手提前积累平台与案例知识，出现问题后能先诊断，再共同修改。这里记录排查方法，不把尚未验证的限制机制写成平台事实。

### 学什么，怎样保存

1. 平台依据：优先查抖音当前官方规则、创作者后台说明和针对本作品的正式通知。每条记录来源链接、核对日期、适用范围及实际支持的结论；电商、广告、直播、开放平台规则不能直接套到普通视频。
2. 外部经验：用户可提供豆包回答、运营教程和创作者案例。拆成可核验命题，查原始来源、完整上下文、反例及其他解释。其他AI的判断属于线索，不因来自某个模型就提升可信度。
3. 本账号证据：每次在本条《发布与复盘.md》记录症状、检查、修改和后续结果。优先保留具体通知、准确时间、真实数据与修改版本；发布状态发生变化及时同步项目简报。
4. 后续复用：出现同类问题时，先读本节与相关作品记录，再查当时有效的平台信息。可靠技术修复按第六节沉淀；内容和分发经验保持适用范围与不确定性，不因单次恢复播放就写成算法定律。

### 固定排查顺序

| 顺序 | 要确认的问题 | 证据与下一步 |
|---|---|---|
| 1. 作品和时间 | 是哪一条、何时发布、何时采集、期间是否改过权限或重发 | 核对作品链接/标题、原始发布页和记录；不把不同作品的播放混在一起 |
| 2. 可见性 | 朋友没刷到、主页找不到，还是直接链接打不开 | 查看实际公开范围、审核/违规提示、朋友打开链接的具体提示；一次打开成功只证明该访问者当时可见 |
| 3. 分发 | 已有播放来自推荐、主页、搜索还是分享 | 只记录后台真实提供的流量来源；总播放大于零不证明已进入推荐，更不证明不存在推荐限制 |
| 4. 内容与账号 | 是否有针对本作品/账号的提示；具体镜头和表达是否需核查 | 对照实际成片、字幕、口播、封面、正文和简介，检查外链/联系方式及引导语境、素材来源与加工、事实承诺、AI标识；这些是检查项，不是已经查明的原因 |
| 5. 观看表现 | 在有真实播放样本后，观众在哪里离开 | 用实际留存和对应时间码分析开场、信息密度、音画；零样本时不评价完播率或封面效果 |

### 关于“官网/软件界面导致软拦截”

- 将“软拦截”视为对现象的待验证描述；没有平台依据时不把它写成确定的后台状态。
- 分开检查：提及OpenAI/Codex、展示软件功能、显示网址、引导到站外领取或交易、介绍网络访问方式。这些语境不同，不能只看到名称就归为同一问题。
- 截至2026-09-06本次检索，没有取得支持“出现OpenAI官网或Codex界面就必然被限制”的官方依据；这不等于证明它们在任何语境下都不会触发审核。本次未完成逐帧诊断或后台核验。
- [抖音用户服务协议](https://www.douyin.com/agreements/?id=6773906068725565448)已打开核对，页面标注2026-02-13更新、2026-02-20生效，可作为发布规范入口，不能单独证明本作品被限制的原因。既有社区公约链接本次抓取超时，不能声称已重新读到该页面。

### 每次应交付什么

按“已知事实 → 优先排查的2—3个原因 → 每个原因的支持/反对证据 → 缺失信息 → 最小验证动作 → 有依据的修改建议”给出诊断。证据不足就明确暂不能判断，不编造概率。

修改建议要落到时间码、原画面/原句、拟修改内容、理由、保留的原意和验证方式。先保留原版和数据，再做可逆的小范围修改；不要为了试原因反复删除重发或同时改多个变量。若平台有明确提示，优先按提示修正或使用官方反馈渠道；发送申诉/反馈须取得用户授权。

修改后记录复查时间、平台状态、可见性与流量来源变化。即使恢复播放，也要保留“审核自然完成、数据延迟等其他解释”，不能立即认定某个词或镜头是原因。约定复查时点不代表设置了自动监测。

2026-09-06核验补充：[DOU+服务协议](https://sf1-draftcdn-tos.pstatp.com/obj/ies-hotsoon-draft/douplus/service.html)（2026-01-01生效）第二部分第3项及第四部分第3—4项对加热内容和投放另设限制条件。因此“不适合加热”可以作为线索，但不能单凭它确认自然推荐受限或归因到画面；先记录完整提示，并查作品和账号状态，不自动删除重发，不要求用户花钱做通用诊断。
