# 剪辑规范

## 核心顺序

先锁内容和节奏，再锁视觉语言，最后完成整片和发布预览。自动化只能提出候选剪点，不能未经听看直接删停顿或决定终稿。

## 基本约束

1. 原片只读，工程、缓存、预览和导出使用独立目录。
2. 口播是真实时间主轨，字幕、卡片、证据、高亮和音效绑定实际录音落点。
3. 不擅自整段倍速、变调、强降噪或 AI 增强；需要时先做对比样片。
4. 无意义空白、明显口误和重复可以提出剪点；思考停顿、呼吸和情绪留白不能只按音量阈值删除。
5. 结构未锁定前不批量制作精细动效。
6. 主画面、人物小窗、字幕、动态重音、证据标注、SFX 和 BGM 分轨管理并逐层锁定。

## 审片关卡

- 素材盘点与粗剪地图：标记问题和候选剪点；
- R1 粗剪：确认顺序、内容、停顿和节奏；
- R2 代表性样片：确认构图、字体、字幕、小窗、转场、动效和音量关系；
- V1 完整审片：使用时间码集中反馈；
- 最终导出：移除临时标记，检查母版和上传预览。

用户可在素材已确认后明确要求跳过逐轮粗剪预览、直接合成；这种决定只适用于当条案例，不改写全局默认流程。

## 转场和节奏

优先使用直接切、声音桥、语义承接、J-cut、L-cut 和新画面自身的进入动作。语义跨度明显时可使用克制推近、压暗或短淡化；同一条通常保持 2—3 类稳定语言，不为每个段落换花样。

## 版本和反馈

预览使用 `R1_粗剪`、`R2_风格样片`、`V1_完整审片` 等可追溯命名，不覆盖上一版。反馈格式建议为“时间码 + 保留/删除/修改 + 原因或目标”，并标记已改、保留原版或待决定。

## 建议分轨

```text
V7  来源、年份和必要合规标注
V6  动态重音及对应音效标记
V5  普通口播字幕
V4  图标、卡片、流程、数据和批注
V3  真人小窗
V2  论文、网站和其他替换主画面
V1  原片安全底轨

A3  BGM（若采用）
A2  SFX
A1  口播主音轨
```

## 最终质检

从头到尾看一遍成片，核对分辨率、帧率、时长、音轨、音画同步、句首、字幕、转场边缘、人物小窗、证据退场、隐私和末帧。电脑检查完整画质，手机检查可读性、音量和注意力焦点，再进入平台上传预览。

HyperFrames Studio 是预览服务，不是成片。黑屏、卡住或无声应先排查服务、重复标签页和解码状态；固定工程 CLI 版本，升级在副本中验证。

- [HyperFrames](https://github.com/heygen-com/hyperframes)：确定性 HTML、CSS、媒体与时间线渲染；
- [Adobe J-cut 与 L-cut](https://helpx.adobe.com/sg/premiere/desktop/edit-projects/trim-clips/perform-j-cuts-and-l-cuts.html)；

- [Auto-Editor](https://github.com/WyattBlue/auto-editor) 仅作为候选剪点工具。

这些资料用于提炼跨软件方法，不代表项目必须购买或使用对应软件。
